# 📊 Пример вывода команды `make status`

Команда `make status` предоставляет полный обзор состояния всех Docker сервисов.

## Как использовать

```bash
cd devops
make status
```

## Что проверяется

### 📊 Статус контейнеров
- Имена всех контейнеров
- Текущий статус (Up/Down)
- Проброшенные порты

### 🏥 Health Checks
- **PostgreSQL**: проверка healthcheck контейнера
- **Bot**: проверка что контейнер запущен
- **API**: проверка что контейнер запущен
- **Frontend**: проверка что контейнер запущен

### 🌐 Доступность сервисов
Реальная проверка HTTP запросами:
- **API Health**: `curl http://localhost:8000/health`
- **API Docs**: `curl http://localhost:8000/docs`
- **Frontend**: `curl http://localhost:3000`
- **Database**: `pg_isready` проверка

### 💾 База данных
Запрос к PostgreSQL для подсчета:
- Количество пользователей в таблице `users`
- Количество сообщений в таблице `messages`

### 💻 Использование ресурсов
Для каждого контейнера:
- Использование CPU в процентах
- Использование RAM (текущее / лимит)

## Интерпретация результатов

### Все хорошо ✅
Если вы видите все зеленые галочки (✅), значит:
- Все контейнеры запущены
- PostgreSQL прошел healthcheck
- API отвечает на запросы
- Frontend доступен
- База данных работает

### Проблемы ❌
Красный крестик (❌) указывает на проблему:
- **PostgreSQL stopped**: база не запустилась
- **API недоступен**: контейнер работает, но API не отвечает
- **Frontend недоступен**: возможна ошибка в коде или сборке
- **Database недоступна**: проблема с подключением к PostgreSQL

### Предупреждения ⚠️
Желтый восклицательный знак (⚠️) означает:
- Контейнеры еще не запущены (нужно сделать `make up`)
- Нет доступа к БД (возможно, миграции не применились)

### В процессе ⏳
Песочные часы (⏳) означают:
- PostgreSQL запускается, но еще не прошел healthcheck
- Обычно проходит за 5-10 секунд

## Использование в workflow

### Быстрая диагностика
```bash
make status
```
Одна команда покажет все проблемы

### Мониторинг после изменений
```bash
# Внесли изменения в код
make restart

# Подождали пару секунд
make status

# Проверили что все работает
```

### CI/CD интеграция
```bash
# В скриптах можно проверять статус
make status | grep "✅" | wc -l
# Если 8 галочек - все работает
```

### Debug workflow
```bash
# 1. Проверить общий статус
make status

# 2. Если есть проблемы, смотрим логи
make logs-api  # или logs-bot, logs-frontend

# 3. Перезапускаем проблемный сервис
docker compose restart api

# 4. Проверяем снова
make status
```

## Технические детали

Команда `make status` выполняет:
1. `docker compose ps` - статус контейнеров
2. `grep` проверки на статусы Up/healthy
3. `curl` запросы к endpoints
4. `pg_isready` для PostgreSQL
5. SQL запросы для подсчета данных
6. `docker stats` для ресурсов

Все проверки выполняются быстро (~1-2 секунды) и не нагружают систему.

## Сравнение с другими командами

| Команда | Что показывает | Когда использовать |
|---------|----------------|-------------------|
| `make status` | Полный статус с проверками | Первая команда для диагностики |
| `make ps` | Только список контейнеров | Быстро проверить что запущено |
| `make stats` | Только ресурсы CPU/RAM | Проверить нагрузку |
| `docker compose ps` | Базовый статус | Минималистичный вывод |

## Полезные комбинации

```bash
# Запустить и сразу проверить статус
make up-daemon && sleep 15 && make status

# Следить за статусом (обновлять каждые 5 секунд)
watch -n 5 make status

# Статус в файл для анализа
make status > status.txt
```
