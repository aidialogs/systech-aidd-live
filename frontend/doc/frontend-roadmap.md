## F1: Требования к дашборду и Mock API

### Цели

- Определить функциональные требования к дашборду статистики
- Спроектировать API для работы с frontend
- Создать mock-реализацию API для разработки frontend

### Состав работ

- ✅ Формирование емких и лаконичных функциональных требований к дашборду для статистики по диалогам (без доработок backend, на основе существующих данных)
- ✅ Референс для дашборда https://ui.shadcn.com/blocks#dashboard-01 (4 блока + таймлайн, без таблиц)
- ✅ Проектирование контракта API для frontend (KISS-подход: один метод для статистики под требования UI)
- ✅ Проектирование интерфейса `StatCollector` с возможностью двух реализаций: Mock и Real
- ✅ Реализация Mock-реализации сборщика статистики (фиксированный набор данных, без random генерации)
- ✅ Автоматическая генерация документации API
- ✅ Создание entrypoint для запуска API-сервера (FastAPI)
- ✅ Создание команд для запуска API и тестирования получения статистики

### Результаты

- 📄 **Документация:** [Функциональные требования](dashboard-requirements.md) · [Итоги спринта](sprint-f1-summary.md)

- 📚 **Автодокументация:** http://localhost:8000/docs (Swagger UI)
- 🚀 **Запуск:** `make api-run` · **Тесты:** `make api-test`

## F2: Каркас frontend проекта

**Статус:** ✅ Completed  
**Дата завершения:** 2025-10-17  
**План спринта:** [s2-init-plan.md](plans/s2-init-plan.md)

### Цели

- Определить технологический стек frontend
- Создать структуру проекта
- Настроить инструменты разработки

### Состав работ

- ✅ Генерация концепции frontend проекта: определение идеи приложения и требований к пользовательскому интерфейсу (документ `frontend/doc/frontend-vision.md` по аналогии с `@doc/vision.md`)
- ✅ Выбор технологического стека: анализ и выбор оптимального набора frontend технологий (ADR-07)
- ✅ Создание структуры проекта Next.js с TypeScript и Tailwind CSS
- ✅ Установка и настройка shadcn/ui (компоненты button, card)
- ✅ Настройка инструментов разработки (ESLint, Prettier, TypeScript strict mode)
- ✅ Создание команд запуска dev-сервера и проверки качества кода (Makefile)

### Что реализовано

**Технологический стек:**

- Next.js 15.5.6 с App Router
- React 19.1.0
- TypeScript 5.9.3 (strict mode)
- shadcn/ui на базе Radix UI
- Tailwind CSS 4.1.14
- pnpm 10.16.1

**Структура проекта:**

```
frontend/
├── app/           # Next.js App Router (layout, page, globals.css)
├── components/
│   ├── ui/        # shadcn/ui компоненты (button, card)
│   ├── dashboard/ # Для Sprint F3
│   └── chat/      # Для Sprint F4
├── lib/
│   ├── utils.ts   # Утилиты (cn helper)
│   └── api.ts     # API client для backend
├── types/
│   └── api.ts     # TypeScript типы для API
└── doc/           # Документация
```

**Команды разработки (Makefile):**

- `make frontend-install` - установка зависимостей
- `make frontend-dev` - запуск dev-сервера (http://localhost:3000)
- `make frontend-build` - production сборка
- `make frontend-lint` - проверка ESLint
- `make frontend-format` - форматирование Prettier
- `make frontend-type-check` - проверка TypeScript
- `make frontend-check-all` - полная проверка (lint + types)

### Результаты

- 📄 **Документация:** [Frontend Vision](frontend-vision.md) · [ADR-07](../../doc/adrs/ADR-07.md) · [План спринта](plans/s2-init-plan.md)
- 🎨 **UI Library:** shadcn/ui с компонентами button и card
- ⚙️ **Инструменты:** ESLint + Prettier + TypeScript strict mode
- 🚀 **Запуск:** `make frontend-dev` (http://localhost:3000)
- ✅ **Проверка:** `make frontend-check-all` проходит без ошибок

## F4: Реализация ИИ-чата

### Цели

- Реализовать веб-интерфейс для администраторского чата
- Создать API для обработки запросов чата
- Интегрировать LLM для ответов на вопросы по статистике (режим администратора)

### Состав работ

- Реализация UI чата на основе референса @21th-ai-chat.md
- Интеграция в дашбоард Floating Button в правом нижнем углу
- Реализация API для чата (аналог функциональности бота)
- **Опционально:** Реализация функционала для администратора: ответы на вопросы по статистике диалогов через pipeline (вопрос → промпт для text2sql → выполнение SQL → передача результата в LLM → ответ пользователю)
- **Опционально:** Переключение между режимами через toogle

> **Планирование:** выполняется в режиме Plan Mode  
> **Ссылка на план:** будет добавлена после выполнения планирования
