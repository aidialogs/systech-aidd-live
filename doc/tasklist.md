## 🚀 Итерации

### Итерация 1: Базовый работающий бот

**Цель**: Запустить работающий эхо-бот с конфигурацией через .env

**Задачи**:
- [ ] Создать структуру папок согласно @vision.md раздел 3
- [ ] Инициализировать проект: `uv init` (создаст `pyproject.toml`)
- [ ] Добавить зависимости: `uv add aiogram openai python-dotenv`
- [ ] Добавить dev-зависимости: `uv add --dev pytest pytest-asyncio`
- [ ] Создать `.env.example` и `.env` со всеми переменными (см. @vision.md раздел 9)
- [ ] Создать `src/config.py` - Config класс
- [ ] Создать `src/message.py` - Message класс
- [ ] Создать `src/main.py` - точка входа с инициализацией бота
- [ ] Создать `src/message_handler.py` с обработчиками `/start`, `/help`, эхо-ответ
- [ ] Создать `Makefile` с командами: `install`, `run`, `test`, `clean`
- [ ] Установить зависимости: `make install` или `uv sync`

**Тест**: 
- `make run` или `uv run python -m src.main` → бот запускается
- Отправить `/start` → получить приветствие
- Отправить текст → получить эхо
- Изменить токен в .env → бот использует новый токен

---

### Итерация 2: Интеграция с LLM

**Цель**: Бот отвечает через OpenRouter API

**Задачи**:
- [ ] Создать `src/llm_client.py` - LLMClient класс согласно @vision.md раздел 6
- [ ] Реализовать метод `async get_response(messages)` → ответ от LLM
- [ ] Создать `src/context_manager.py` - ContextManager класс
- [ ] В message_handler.py заменить эхо на вызов LLMClient
- [ ] Добавить системный промпт из конфигурации
- [ ] Простая обработка ошибок API (try/except)

**Тест**:
- Отправить вопрос → получить ответ от LLM
- Убрать API ключ → получить сообщение об ошибке

---

### Итерация 3: Логирование

**Цель**: Все события записываются в лог-файл

**Задачи**:
- [ ] Настроить logging согласно @vision.md раздел 10
- [ ] Создать папку `logs/` (добавить в .gitignore)
- [ ] Добавить логи в message_handler.py: входящие/исходящие сообщения
- [ ] Добавить логи в llm_client.py: запросы/ответы/ошибки
- [ ] Добавить логи запуска/остановки бота в main.py

**Тест**:
- Отправить сообщения → проверить `logs/app.log`
- Вызвать ошибку API → ошибка в логе

---

### Итерация 4: История диалогов

**Цель**: Бот помнит контекст разговора

**Задачи**:
- [ ] Создать структуру `dialog_history` согласно @vision.md раздел 5
- [ ] Сохранять сообщения пользователя и бота в историю
- [ ] Передавать полную историю в LLM при каждом запросе
- [ ] Ограничить историю `MAX_HISTORY_LENGTH` сообщениями
- [ ] Добавить команду `/reset` для очистки истории (опционально)

**Тест**:
- Диалог из 3-4 сообщений → бот помнит контекст
- Перезапуск бота → история очищена

---

### Итерация 5: Финализация

**Цель**: Проект готов к использованию

**Задачи**:
- [ ] Создать `README.md` с инструкциями по запуску
- [ ] Проверить `.env.example` - все переменные описаны
- [ ] Проверить `pyproject.toml` - все зависимости и метаданные корректны
- [ ] Добавить простые pytest тесты для критичных функций (LLMClient, ContextManager)
- [ ] Финальное тестирование всех сценариев из @vision.md раздел 8
- [ ] Очистить код от временных комментариев
- [ ] Убедиться что `Makefile` работает корректно

**Тест**:
- Полный цикл: клонирование → `uv sync` → настройка .env → `make run` → диалог
- Все команды бота работают (/start, /help, /reset)
- Логи пишутся корректно в `logs/app.log`
- `make test` запускает тесты успешно

---

## 📝 Примечания

- **Каждая итерация должна быть работающей** - можно остановиться на любой
- **Тестируем сразу** - не накапливаем непроверенный код
- **Простота превыше всего** - см. @conventions.md
- **Документация минимальна** - только README.md

## 🔧 Команды для разработки

```bash
# Инициализация проекта (создает pyproject.toml)
uv init

# Добавить зависимость
uv add package_name
uv add --dev pytest

# Установка зависимостей
make install
# или напрямую
uv sync

# Запуск бота
make run
# или напрямую
uv run python -m src.main

# Запуск тестов
make test
# или напрямую
uv run pytest

# Просмотр логов
tail -f logs/app.log

# Очистка временных файлов
make clean
```
