# ADR-02: Использование aiogram для разработки Telegram-бота

**Статус:** Принято  
**Дата:** 2025-10-10  
**Авторы:** Команда разработки

## Контекст

Для реализации LLM-ассистента в виде Telegram-бота необходимо выбрать библиотеку для работы с Telegram Bot API. Требования:

- Асинхронная работа для эффективной интеграции с LLM API
- Поддержка управления контекстом диалога
- Простота разработки и поддержки
- Высокая производительность при масштабировании
- Современный подход к разработке (async/await)

## Решение

Выбрана библиотека **aiogram 3.x** в качестве основного фреймворка для разработки Telegram-бота.

### Ключевые преимущества:

1. **Async-first архитектура** - изначально разработан для asyncio, что идеально сочетается с асинхронными LLM клиентами
2. **Встроенная FSM** - Finite State Machine для управления состоянием диалогов и контекстом
3. **Middleware система** - гибкая обработка запросов и ответов
4. **Современный API** - интуитивный и pythonic подход к разработке
5. **Производительность** - высокая скорость обработки обновлений

### Технические характеристики:

- Полная поддержка Telegram Bot API
- Type hints для статической проверки типов
- Router система для организации handlers
- Встроенная поддержка фильтров
- Webhook и polling режимы

## Последствия

### Положительные:

- ✅ **Идеальная интеграция с async LLM API** - естественная работа с OpenAI, Ollama и другими async клиентами
- ✅ **Управление контекстом** - FSM упрощает хранение и управление состоянием диалога
- ✅ **Высокая производительность** - быстрая обработка большого количества запросов
- ✅ **Простота кода** - чистый и понятный синтаксис
- ✅ **Масштабируемость** - легко расширять функционал через middleware и роутеры
- ✅ **Легковесность** - минимальные зависимости, быстрый старт проекта
- ✅ **Активная разработка** - регулярные обновления и поддержка актуальной версии Bot API

### Отрицательные:

- ⚠️ **Меньшее сообщество** - по сравнению с python-telegram-bot
- ⚠️ **Меньше примеров** - в интернете меньше готовых решений
- ⚠️ **Документация** - местами менее подробная, чем у конкурентов
- ⚠️ **Breaking changes** - aiogram 3.x существенно отличается от 2.x

### Риски и митигация:

- **Риск:** Недостаточно примеров для сложных сценариев
  - *Митигация:* Использование официальной документации и активного Telegram-чата сообщества
  
- **Риск:** Изменения в API между версиями
  - *Митигация:* Фиксация версии в requirements.txt, следование changelog при обновлениях

## Альтернативы

### 1. python-telegram-bot
**Описание:** Наиболее популярная библиотека для Telegram ботов

- ✅ Самое большое сообщество
- ✅ Максимальная документация и примеры
- ✅ Полная поддержка всех функций Bot API
- ❌ Более сложный API
- ❌ Тяжелее для простых задач
- ❌ Больше boilerplate кода

### 2. pyTelegramBotAPI (telebot)
**Описание:** Простая и легкая библиотека

- ✅ Максимальная простота для новичков
- ✅ Минимальные зависимости
- ✅ Sync и async режимы
- ❌ Меньше возможностей для управления состоянием
- ❌ Менее подходит для сложных диалогов
- ❌ Ограниченная система middleware

### 3. Telethon
**Описание:** MTProto клиент с расширенными возможностями

- ✅ Прямой доступ к MTProto API
- ✅ Работа от имени пользователя
- ❌ Избыточность функционала для бота
- ❌ Более высокий порог входа
- ❌ Сложнее в поддержке

## Обоснование выбора

aiogram выбран как оптимальное решение по следующим причинам:

1. **Синергия с ADR-01** - async-first подход идеально сочетается с асинхронными LLM клиентами (OpenAI SDK)
2. **Управление диалогом** - встроенная FSM решает задачу поддержки контекста беседы из коробки
3. **Скорость разработки** - простой API позволяет быстро создать MVP
4. **Производительность** - эффективная обработка запросов важна для LLM-ассистента
5. **Современность** - актуальный стек технологий (asyncio, type hints)

### Пример интеграции с LLM:

```python
from aiogram import Bot, Dispatcher, types
from aiogram.filters import Command
from openai import AsyncOpenAI

bot = Bot(token="TOKEN")
dp = Dispatcher()
llm_client = AsyncOpenAI(base_url="...", api_key="...")

@dp.message(Command("start"))
async def start_handler(message: types.Message):
    await message.answer("Привет! Я LLM-ассистент.")

@dp.message()
async def message_handler(message: types.Message):
    response = await llm_client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": message.text}]
    )
    await message.answer(response.choices[0].message.content)
```
