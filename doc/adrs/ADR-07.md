# ADR-07: Выбор технологического стека для Frontend проекта

**Статус:** Принято  
**Дата:** 2025-10-17  
**Авторы:** Команда разработки  
**Связанные ADR:** ADR-01 (OpenAI Compatible API), ADR-06 (PostgreSQL + SQLAlchemy)

## Контекст

Для реализации пользовательского интерфейса проекта systech-aidd-live необходимо выбрать технологический стек frontend разработки. Требования:

- Быстрая разработка дашборда статистики и веб-чата
- Интеграция с FastAPI backend (Sprint F1)
- Современный UI с готовыми компонентами
- Типобезопасность и качество кода
- Адаптивный дизайн (desktop, tablet, mobile)
- Хорошая производительность и SEO

В Sprint F1 был создан Mock API для статистики, теперь необходимо создать frontend для отображения данных.

## Решение

Выбран следующий технологический стек:

- **Framework:** Next.js 15+
- **Язык:** TypeScript 5+
- **UI Library:** shadcn/ui
- **Styling:** Tailwind CSS
- **Пакетный менеджер:** pnpm

### Архитектурные решения

1. **Next.js App Router** - современная файловая маршрутизация
2. **React Server Components** - оптимизация производительности
3. **TypeScript strict mode** - максимальная типобезопасность
4. **Копирование компонентов** - shadcn/ui компоненты в проекте (не npm)
5. **Utility-first CSS** - Tailwind для быстрой стилизации

## Обоснование выбора

### Next.js 15+

**Плюсы:**
- ✅ **App Router** - современная маршрутизация с Server Components
- ✅ **Оптимизации из коробки** - Image, Font, Script optimization
- ✅ **API Routes** - возможность проксирования запросов к backend
- ✅ **TypeScript поддержка** - first-class support
- ✅ **Server Components** - меньше JavaScript на клиенте
- ✅ **Streaming SSR** - быстрый First Contentful Paint
- ✅ **Built-in optimizations** - Code Splitting, Tree Shaking
- ✅ **Production ready** - используется крупными компаниями

**Минусы:**
- ⚠️ **Сложность** - больше концепций чем у CRA
- ⚠️ **Learning curve** - требуется изучение App Router
- ⚠️ **Размер** - больше зависимостей чем у Vite

**Вердикт:** Оптимальный выбор для production приложения с SSR и оптимизацией.

### TypeScript 5+

**Плюсы:**
- ✅ **Статическая типизация** - меньше runtime ошибок
- ✅ **Автодополнение** - лучший Developer Experience
- ✅ **Refactoring safety** - безопасные изменения кода
- ✅ **Интеграция с shadcn/ui** - готовые типы для компонентов
- ✅ **Strict mode** - максимальная типобезопасность
- ✅ **Self-documenting code** - типы как документация

**Минусы:**
- ⚠️ **Overhead** - дополнительное время на написание типов
- ⚠️ **Learning curve** - требуется знание TypeScript

**Вердикт:** Необходим для качественного кода, особенно в команде.

### shadcn/ui

**Плюсы:**
- ✅ **Copy-paste approach** - компоненты копируются в проект (не npm пакет)
- ✅ **Полный контроль** - можно модифицировать любой компонент
- ✅ **Radix UI primitives** - accessibility из коробки (ARIA, keyboard navigation)
- ✅ **Tailwind styling** - легко кастомизировать стили
- ✅ **TypeScript** - полная типизация
- ✅ **Готовые dashboard блоки** - референс из Sprint F1 (shadcn.com/blocks)
- ✅ **Современный дизайн** - актуальные UI паттерны
- ✅ **Легковесность** - только нужные компоненты

**Минусы:**
- ⚠️ **Ручные обновления** - нет автоматических обновлений через npm
- ⚠️ **Больше кода в проекте** - компоненты копируются

**Вердикт:** Идеальный баланс между контролем и готовыми решениями.

**Примечание:** Референс дашборда из Sprint F1 основан именно на shadcn/ui blocks, что упрощает реализацию.

### Tailwind CSS

**Плюсы:**
- ✅ **Utility-first** - быстрая разработка без написания CSS
- ✅ **Встроенная темизация** - CSS переменные для dark mode
- ✅ **Responsive design** - breakpoints для адаптивности
- ✅ **Оптимизация** - PurgeCSS удаляет неиспользуемые стили
- ✅ **Интеграция с shadcn/ui** - нативная поддержка
- ✅ **Консистентность** - design tokens через конфиг
- ✅ **IntelliSense** - автодополнение в VS Code

**Минусы:**
- ⚠️ **Читаемость** - длинные строки классов
- ⚠️ **Learning curve** - нужно знать utility классы

**Вердикт:** Стандарт индустрии для modern web apps.

### pnpm

**Плюсы:**
- ✅ **Скорость** - быстрее npm и yarn
- ✅ **Дисковое пространство** - symlinks вместо копирования
- ✅ **Строгость** - изолированные зависимости (no phantom dependencies)
- ✅ **Monorepo support** - если понадобится в будущем
- ✅ **Совместимость** - работает с любыми npm пакетами
- ✅ **Меньше baggage** - экономия места в node_modules

**Минусы:**
- ⚠️ **Меньшее распространение** - чем npm/yarn
- ⚠️ **Команды отличаются** - немного другой CLI

**Вердикт:** Современный стандарт для новых проектов.

## Альтернативы

### 1. Vite + React

**Описание:** Быстрый dev-сервер с React без фреймворка

- ✅ Очень быстрый HMR
- ✅ Минимальная конфигурация
- ✅ Легковесность
- ❌ Нет SSR из коробки
- ❌ Нужно настраивать роутинг (react-router)
- ❌ Меньше оптимизаций для production
- ❌ Нет встроенного API layer

**Вердикт:** Подходит для SPA, но Next.js дает больше возможностей для нашего кейса.

### 2. Create React App

**Описание:** Официальный стартер для React приложений

- ✅ Простота для новичков
- ❌ **Deprecated** - больше не поддерживается
- ❌ Медленный dev-сервер
- ❌ Устаревший tooling (Webpack 4)

**Вердикт:** Устарел, не рассматривается.

### 3. Vue 3 / Nuxt

**Описание:** Альтернативный фреймворк с похожими возможностями

- ✅ Проще для новичков
- ✅ Хорошая производительность
- ❌ Команда знает React лучше
- ❌ Меньше готовых UI библиотек
- ❌ shadcn/ui для React

**Вердикт:** Хороший фреймворк, но React более знаком команде.

### 4. Svelte / SvelteKit

**Описание:** Компилируемый фреймворк без Virtual DOM

- ✅ Высокая производительность
- ✅ Меньше boilerplate
- ❌ Меньшая экосистема
- ❌ Команда не знакома со Svelte
- ❌ Меньше готовых компонентов

**Вердикт:** Интересная технология, но React экосистема богаче.

### 5. Material UI (MUI)

**Описание:** Альтернативная UI библиотека вместо shadcn/ui

- ✅ Огромное количество компонентов
- ✅ Зрелая библиотека
- ❌ Тяжелая (большой bundle size)
- ❌ Сложная кастомизация темы
- ❌ Material Design стиль (не все подходит)
- ❌ npm пакет (нет контроля над кодом)

**Вердикт:** Слишком тяжелая для нашего проекта.

### 6. Ant Design

**Описание:** Enterprise UI библиотека

- ✅ Много компонентов для admin панелей
- ✅ Dashboard готовые решения
- ❌ Тяжелая (большой bundle)
- ❌ Специфичный дизайн (Chinese-oriented)
- ❌ Сложнее кастомизация

**Вердикт:** Избыточно для нашего кейса.

### 7. npm / yarn вместо pnpm

**npm:**
- ✅ Стандарт, идет с Node.js
- ❌ Медленнее pnpm
- ❌ Больше занимает места

**yarn:**
- ✅ Быстрее npm
- ❌ Медленнее pnpm
- ❌ yarn v1 устарел, v2+ сложнее

**Вердикт:** pnpm современнее и эффективнее.

## Последствия

### Положительные

- ✅ **Быстрая разработка** - готовые компоненты shadcn/ui ускоряют разработку
- ✅ **Type safety** - TypeScript предотвращает ошибки
- ✅ **Performance** - Next.js оптимизации из коробки
- ✅ **Developer Experience** - отличный DX с HMR, TypeScript, ESLint
- ✅ **Accessibility** - Radix UI primitives обеспечивают доступность
- ✅ **Responsive** - Tailwind упрощает адаптивный дизайн
- ✅ **Maintainability** - контроль над компонентами shadcn/ui
- ✅ **SEO готовность** - Server Components для лучшей индексации

### Отрицательные

- ⚠️ **Learning curve** - требуется изучение Next.js App Router
- ⚠️ **Сложность** - больше концепций чем у простого React SPA
- ⚠️ **Ручные обновления** - shadcn/ui компоненты нужно обновлять вручную
- ⚠️ **Overhead** - TypeScript добавляет времени на разработку

### Риски и митигация

**Риск:** Сложность Next.js App Router для новых разработчиков
- *Митигация:* Документация в frontend-vision.md, примеры кода, онбординг

**Риск:** Ручные обновления shadcn/ui компонентов
- *Митигация:* Следим за changelog, обновляем при необходимости

**Риск:** TypeScript может замедлить начальную разработку
- *Митигация:* Выигрыш в качестве кода компенсирует затраченное время
