## Когда проводить code review

1. **После завершения крупных итераций** - проверка соответствия соглашениям
2. **Перед деплоем в production** - финальная проверка качества
3. **После рефакторинга** - убедиться что не появилось регрессий
4. **Периодически** (раз в неделю/спринт) - поддержание качества кода

## Процесс code review

Используйте команду `/review` в Cursor для автоматического проведения review согласно workflow из `.cursor/commands/review.md`.

Процесс включает:
1. Чтение всех соглашений (conventions, vision, ADRs)
2. Проверка соответствия кода соглашениям
3. Запуск всех метрик (lint, test, coverage)
4. Анализ архитектуры
5. Создание подробного отчета
6. Исправление критических замечаний (если есть)
