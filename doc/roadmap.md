## 📝 Описание спринтов

### Спринт S0: MVP + Tech Debt Elimination

**Цель:**  
Создать минимально жизнеспособный продукт (MVP) - Telegram-бот с интеграцией LLM и управлением контекстом диалога, затем провести итеративное устранение технического долга для достижения production-ready качества.

**Предполагаемый план:**
- **MVP (итерации 0-5):**
  - 0️⃣ Эхо-бот - базовая архитектура с MessageHandler-заглушкой
  - 1️⃣ Интеграция LLM - подключение OpenAI API
  - 2️⃣ Интеграция истории диалога - ContextManager с in-memory хранением
  - 3️⃣ Команды и обрезка истории - `/start`, `/help`, `/reset`, ограничение контекста
  - 4️⃣ Финальное тестирование - проверка всех сценариев
  - 5️⃣ Роль AICodingExpert - системный промпт и команда `/role`

- **Tech Debt (итерации 0-4):**
  - 0️⃣ Инструменты качества кода - настройка ruff, mypy, pytest-cov
  - 1️⃣ Type hints + валидация - полная типизация, dataclass Config, custom exceptions
  - 2️⃣ Архитектурный рефакторинг - SOLID принципы, Protocols, CommandHandler
  - 3️⃣ Улучшение тестирования - 100% coverage, fixtures, моки
  - 4️⃣ Финальная проверка качества - документация, ADR, метрики

**Фактический план:**
- ✅ [Tasklist - MVP](tasklists/tasklist-s0.md) - базовый функционал бота (6 итераций)
- ✅ [Tasklist - Tech Debt](tasklists/tasklist_tech_debt-s0.md) - устранение технического долга (5 итераций)

**Достигнутые результаты:**
- ✅ Полностью рабочий Telegram-бот с интеграцией LLM
- ✅ Управление контекстом диалога (in-memory)
- ✅ Команды: `/start`, `/help`, `/reset`, `/role`
- ✅ 100% test coverage (165/165 statements)
- ✅ 0 mypy errors (strict mode)
- ✅ 0 ruff warnings
- ✅ SOLID принципы: SRP, DIP через Protocols
- ✅ Comprehensive test suite: 30 тестов (29 unit + 1 integration)
- ✅ Production-ready код с полной документацией

**Технологии:**
- Python 3.11+, aiogram 3.x, openai, python-dotenv
- Code Quality: ruff, mypy, pytest, pytest-cov, pytest-mock
- Package Manager: uv

**Дата начала:** 2025-10-10  
**Дата завершения:** 2025-10-11

### Спринт S1: Персистентное хранение данных

**Цель:**  
Реализовать сохранение истории диалогов в базе данных вместо текущего in-memory хранения. История диалогов должна сохраняться между перезапусками бота, обеспечивая персистентность данных.

**Предполагаемый план:**
- Анализ требований к данным, выбор технологий (СУБД и инструмента миграций) с документированием решений через ADR
- Настройка локального окружения с СУБД через Docker
- Проектирование схемы базы данных (определение таблиц, связей, индексов, создание ER-диаграмм)
- Реализация системы миграций для управления версиями схемы БД
- Разработка слоя доступа к данным
- Рефакторинг приложения для использования БД вместо in-memory хранения

**Фактический план:**
- ⏳ Будет создан после начала спринта

**Статус:** 📋 Запланирован
