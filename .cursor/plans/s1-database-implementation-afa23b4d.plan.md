# Sprint S1: Персистентное хранение данных

## Технологический стек

- **БД:** PostgreSQL 16 (Docker)
- **ORM:** SQLAlchemy 2.0 (async)
- **Driver:** asyncpg (высокопроизводительный async драйвер)
- **Migrations:** Alembic (автогенерация из моделей)
- **Подход:** Декларативные модели с async ORM

## ER-диаграмма схемы данных

```
┌──────────────────────┐
│       User           │
├──────────────────────┤
│ id (PK) BIGINT       │──┐
│ created_at TIMESTAMP │  │
│ is_deleted BOOLEAN   │  │ 1:N
└──────────────────────┘  │
                          │
                          │
┌──────────────────────┐  │
│      Message         │  │
├──────────────────────┤  │
│ id (PK) SERIAL       │  │
│ user_id (FK) BIGINT  │──┘
│ chat_id BIGINT       │  (не FK)
│ role VARCHAR(20)     │
│ content TEXT         │
│ content_length INT   │
│ created_at TIMESTAMP │
│ is_deleted BOOLEAN   │
└──────────────────────┘
```

**Пояснения к схеме:**

- **User** - Telegram пользователь (хранится только один раз по user_id)
- **Message** - сообщения пользователя в разных чатах
- `user_id` в Message - FK к User (один пользователь → много сообщений)
- `chat_id` в Message - НЕ FK (просто telegram chat_id, не храним Chat отдельно)
- Один User может писать в разных чатах → много Message с разными chat_id
- Для получения контекста: `WHERE user_id = X AND chat_id = Y AND is_deleted = False`

### 2. SQLAlchemy модели

**`src/models.py`** - новый модуль с декларативными моделями

```python
from datetime import datetime
from sqlalchemy import BigInteger, Boolean, DateTime, ForeignKey, Index, Integer, String, Text, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship


class Base(DeclarativeBase):
    """Базовый класс для всех ORM моделей."""
    pass


class User(Base):
    """Пользователь Telegram."""
    __tablename__ = "users"
    
    # Telegram user_id как первичный ключ
    id: Mapped[int] = mapped_column(BigInteger, primary_key=True)
    
    # Метаданные
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), 
        server_default=func.now(),
        nullable=False
    )
    is_deleted: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False)
    
    # Relationships
    messages: Mapped[list["Message"]] = relationship(
        back_populates="user", 
        cascade="all, delete-orphan"
    )


class Message(Base):
    """Сообщение в чате."""
    __tablename__ = "messages"
    
    # Автоинкрементный ID
    id: Mapped[int] = mapped_column(primary_key=True)
    
    # Связи
    user_id: Mapped[int] = mapped_column(BigInteger, ForeignKey("users.id"), nullable=False)
    chat_id: Mapped[int] = mapped_column(BigInteger, nullable=False)
    
    # Данные сообщения
    role: Mapped[str] = mapped_column(String(20), nullable=False)  # system/user/assistant
    content: Mapped[str] = mapped_column(Text, nullable=False)
    content_length: Mapped[int] = mapped_column(Integer, nullable=False)
    
    # Метаданные
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), 
        server_default=func.now(),
        nullable=False
    )
    is_deleted: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False)
    
    # Relationships
    user: Mapped["User"] = relationship(back_populates="messages")


# Индексы для производительности
Index('idx_messages_user_chat', Message.user_id, Message.chat_id, Message.is_deleted, Message.created_at)
Index('idx_users_active', User.is_deleted, User.created_at)
```

**`src/repository.py`** - новый модуль для repository pattern

MessageRepository класс:

- `ensure_user(user_id) -> User` - создает пользователя если не существует
- `add_message(user_id, chat_id, role, content) -> Message` - добавляет сообщение
- `get_messages(user_id, chat_id, limit) -> list[Message]` - получает последние N сообщений для контекста
- `soft_delete_messages(user_id, chat_id) -> int` - soft delete сообщений

**Стратегия управления размером контекста:**

Используем подход **"Ограничение при чтении"** - все сообщения сохраняются в БД, но при получении контекста возвращаются только последние N сообщений.

**Преимущества:**

- Полная история сохранена (для аналитики, отладки)
- Простая реализация
- Быстрые запросы (LIMIT в SQL)
- Не нужно удалять данные

**Реализация `get_messages()`:**

```python
async def get_messages(
    self, 
    user_id: int, 
    chat_id: int, 
    limit: int
) -> list[models.Message]:
    """
    Получить последние N сообщений для контекста.
    System prompt всегда включается первым (не входит в лимит).
    """
    # 1. Получить system prompt (первое сообщение с role='system')
    stmt_system = (
        select(models.Message)
        .where(
            models.Message.user_id == user_id,
            models.Message.chat_id == chat_id,
            models.Message.role == "system",
            models.Message.is_deleted == False
        )
        .order_by(models.Message.created_at.asc())
        .limit(1)
    )
    result = await self.session.execute(stmt_system)
    system_msg = result.scalar_one_or_none()
    
    # 2. Получить последние (limit - 1) не-system сообщений
    stmt_messages = (
        select(models.Message)
        .where(
            models.Message.user_id == user_id,
            models.Message.chat_id == chat_id,
            models.Message.role != "system",
            models.Message.is_deleted == False
        )
        .order_by(models.Message.created_at.desc())
        .limit(limit - 1 if system_msg else limit)
    )
    result = await self.session.execute(stmt_messages)
    messages = list(reversed(result.scalars().all()))
    
    # 3. Вернуть: [system_prompt] + остальные сообщения
    if system_msg:
        return [system_msg] + messages
    return messages
```

**Логика работы:**

- БД хранит ВСЕ сообщения (is_deleted=False)
- При чтении берем: 1 system prompt + последние (N-1) сообщений
- LLM видит ограниченный контекст, но история полная
- Для аналитики можно получить полную историю без лимита
